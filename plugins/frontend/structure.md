# 前端目录结构

本规范适用于前端页面、组件及其入口。既有项目的框架规定、实际目录与样式栈、明确覆盖优先。例如文件路由的框架保留入口由框架约定决定。下文的 TSX、TS、Less 是 React 和 TypeScript 项目的默认组织，其他栈沿用对应文件类型及构建规则。

## 页面、组件与入口

- 页面和组件使用 `目录名/index.ts + 目录名.tsx + 目录名.module.less`；目录和主组件使用 PascalCase，主 TSX 必须与目录同名。有自有样式时 Less 必须同名；无自有样式不建空 Less。
- 例：`src/pages/Example/Detail/index.ts + Detail.tsx + Detail.module.less`。业务根目录内的子页面继续按此结构递归组织，不能将子页实现平铺在父目录。
- 每个页面/组件目录仅有一个主 TSX；其他可独立渲染的内容、入口包装或弹层放入 `components/组件名/`，同样具备 `index.ts + 同名 TSX + 可选同名 Less`。
- 登录、空间初始化等页面门禁由同名页面主文件承载；复杂内容视图进入私有组件。不能在根目录并排放 `Xxx.tsx`、`XxxEntry.tsx`、`XxxPage.tsx` 作为未说明的例外。
- 无样式的路由生命周期/Provider 组件仍使用独立同名目录和 `index.ts`；不能因为不渲染 DOM 就直接平铺 TSX。
- 页面、组件的 `index.ts` 只写 `export { default } from './目录名';`，不放初始化、Hook 或 JSX。组件集合目录没有消费者时不创建桶；有聚合消费者时其 index 仅做转导出，不充当页面或组件实现。
- hooks 必须位于 `hooks/`；helpers、utils、types 等非组件职责可以采用普通 TS 文件，不机械包装成组件目录。Hook 即使返回 JSX 仍按 hooks 规则归属。
- `src/api`、`src/types` 按业务域分目录；新增代码遵循业务域拆分，新代码依照当前业务域归属组织。

## 私有与共享边界

- 页面私有组件留在所属页面的 `components/`，不能被其他子页面或业务模块穿透引用。
- 同一业务域多个子页面共用的 UI 放在最近共同业务根的 `components/`；跨业务域且可独立复用的 UI 放 `src/components/`。
- 深度依赖所属领域状态的完整业务组合不为跨域复用而整体搬入公共组件层。可由领域根提供具名、窄范围的公开 TS 转导出入口，文档说明所有权、输入输出和消费者；reviewer 必须确认这是业务契约，不能仅为绕过私有目录检查增加转导出。
- 同目录入口可引用主文件；跨目录消费者必须走组件目录入口，不能穿透 `Component/Component.tsx`。样式只能由同目录同名实现导入，不借用其他组件的 module.less。
- 新增、移动或重命名之前先确定页面/组件所属模块、私有或共享范围、主文件及桶入口；完成后同时检查实际消费者，不以现有不规范目录作为新代码模板。

## 审查与验证

- 新增、移动、重命名页面或组件时，逐目录核对所属模块、公开入口、同名主实现、可选样式和消费者。新增消费者时核对被消费实现的所有权，避免页面私有实现被跨页绕过。
- 领域公开入口应记录业务契约并追到实际实现与调用方，核对状态和生命周期所有权。动态引用及实际归属需结合源码判断。
- 从项目约定获取结构检查，核对覆盖工作区还是暂存区。增量通过仅表示未发现新违规。涉及结构契约变化时查受限反例与合法例外；已有历史问题单独记录。
