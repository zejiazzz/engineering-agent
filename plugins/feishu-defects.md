# 飞书缺陷处理

适用于以飞书文档、知识库或多维表格为缺陷来源的项目。先读取项目适配器（若已登记）与当前任务。适配器负责字段含义、记录筛选、状态映射、责任归属、项目验证和本地状态存放。字段等信息可以从实时表结构和用户明确给出的范围确定。回写所需的状态含义无法确认时，继续可独立完成的读取和本地工作。

## 取证与排查

1. 按当前宿主可用方式读取飞书。知识库链接先解析目标类型，文档读取正文及相关附件，多维表格读取目标表、视图、字段和目标记录。使用所在环境可用的飞书连接器，或按现有 `lark-wiki`、`lark-doc`、`lark-base` 等 Skill 选择工具。将查询与统计限定在用户要求的视图、记录和筛选条件内。
2. 每次复核、续作或写入，按稳定记录 ID 刷新来源。记录读取时间、实际和预期行为、环境、可用版本、附件及证据缺口。历史缓存可恢复范围、排除项和进度。只有刷新结果支持其仍适用时，才复用历史结论。解析附件中的图片、文档或视频时，覆盖能决定结论的内容，注明受限和缺失项。
3. 在项目的真实入口检查触发条件、数据与状态链、消费者和可观察结果，区分已确认根因、待验证推断和证据缺口。只有已确认的根因进入修复。共用根因可一次修复，对每条记录仍保留独立的证据、归属、排除条件和回归场景。项目有额外验收基线时，组合对应已注册插件。

## 修复与状态同步

1. 分别确认本地修复和远端写入的授权。仅统计、分析或拟定方案时，交付观察、根因证据和后续验证。需要认领时先确认执行者、前置依赖和当前归属。按项目约定允许的范围实施和验证，单独保留自动、人工及远端状态的结果。
2. 每次写入前重新读取目标稳定 ID、当前状态及归属，确认目标值来自实际字段和项目约定。已经处于目标值时跳过，发现冲突时保留他人的更改。对实际写入逐条回读，异常时先确认写入是否生效再重试。不同步时保留本地待同步依据，报告失败或未知状态。分析、修复与验证完成各自需要相应证据，用户对本地操作的授权不会自动授予状态回写。
3. 交付说明实际读取范围、记录数与根因数、代码和验证结果、远端写回或跳过内容、冲突及待补证据。复用项目现有规格或任务记录。凭据和附件中的私密内容遵循项目与宿主的数据处理规则。
